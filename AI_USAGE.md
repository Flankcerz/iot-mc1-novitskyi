## Журнал використання

1. **Етап:** підготовка проєкту
   **Мета:** структура репозиторію, робота у VS Code на Windows
   **Промпт:** «я хочу використовувати вс код»
   **Що взято:** структура папок, `.gitignore`, схема комітів
   **Що змінив:** команди були для Bash, а в мене PowerShell, тому використав варіанти `mkdir` і `ni` для PowerShell
   **Як перевірив:** `tree /F` і дерево файлів у провіднику VS Code

2. **Етап:** брокер Mosquitto (безпека)
   **Мета:** автентифікація, ACL, TLS, секрети поза git
   **Промпт:** «3» (номер мого варіанта) після запиту на конфігурацію для варіанта 3
   **Що взято:** `docker-compose.yml`, `mosquitto.conf`, `acl`, `setup.sh`, `certs/generate.sh`, `.env.example`
   **Що змінив:** імена контейнерів на `mc1-*` (конфлікт зі старими контейнерами), додав `MSYS_NO_PATHCONV=1`, додав `chown/chmod` для `passwd`
   **Як перевірив:** `docker compose logs`, `mosquitto_sub` без пароля (`not authorised`), `mosquitto_pub` від користувача `door` у `lock/set` (`Not authorized`), `netstat` у контейнері (слухає лише 8883)

3. **Етап:** симулятор пристроїв
   **Мета:** дев'ять MQTT-клієнтів із Last Will, retained-статусами та сценаріями
   **Промпт:** запит на симулятор зі сценаріями для трьох правил варіанта 3
   **Що взято:** `simulator/devices.py`
   **Що змінив:** замінив передачу PIN відкритим текстом на SHA-256, вставив код у файл і запустив
   **Як перевірив:** запуск `python devices.py`, `Ctrl+C` і поява `status offline` у спостерігачі `mosquitto_sub`

4. **Етап:** openHAB: Things, Items, sitemap, persistence
   **Мета:** підключення до брокера по TLS, інтерфейс, графік
   **Промпт:** «далі»
   **Що взято:** `mqtt.things.template`, `home.items`, `home.sitemap`, `rrd4j.persist`, `addons.cfg`
   **Що змінив:** виправив часовий пояс, створення truststore і генерацію `mqtt.things` із шаблону
   **Як перевірив:** сторінка Settings → Things (усе ONLINE), Basic UI, `openhab.log`

5. **Етап:** правила автоматизації
   **Мета:** три правила варіанта 3 (PIN 30 с, дим, нічний рух)
   **Промпт:** «просто пиши мені куди вставляти повний код» і «по кроково як все робити»
   **Що взято:** `openhab/conf/rules/security.rules`
   **Що змінив:** замінив спосіб перевірки PIN (див. помилку 7)
   **Як перевірив:** сценарії `intrusion`, `intrusion_pin`, `fire`, `night_motion`, зміни Items у Basic UI, `openhab.log`

6. **Етап:** документація і здача
   **Мета:** README, STRIDE, скріншоти, план здачі
   **Промпт:** «напиши мені по кроково, як здати і що робити щоб захистити модульну роботу»
   **Що взято:** структура README, таблиці топіків і пристроїв, STRIDE, перелік скріншотів
   **Що змінив:** вписав своє ПІБ, групу й логін GitHub, зробив скріншоти сам
   **Як перевірив:** переглянув README на GitHub, звірив імена файлів скріншотів, перевірив у логах брокера, що ім'я користувача логується (твердження зі STRIDE)

## Помилки ШІ, які я знайшов

| № | Що було не так | Як помітив | Як виправив |
|---|---|---|---|
| 1 | ШІ дав команди `mkdir -p ... {a,b}` і `touch` для Bash, а я працюю в PowerShell | PowerShell видав `Missing argument in parameter list` і `touch is not recognized` | команди для PowerShell: `mkdir a, b` і `ni ... -ItemType File` |
| 2 | `certs/generate.sh`: Git Bash перетворив `/CN=IoT-Home-CA` на шлях `C:/Program Files/Git/CN=...` | `openssl` вивів `subject name is expected to be in the format /type0=value0` | додав `export MSYS_NO_PATHCONV=1` на початку скрипта |
| 3 | `passwd`, створений контейнером від root, не читався брокером | у логах `password-file: Error: Unable to open pwfile`, контейнер постійно перезапускався | додав `chown mosquitto` і `chmod 0644` для `passwd` у `setup.sh` |
| 4 | в ACL openHAB не мав права `write` на `home/system/mode/state`, тому не міг публікувати режим охорони | виявлено під час перегляду ACL до запуску правил | додав рядок `topic write home/system/mode/state` для `openhab` |
| 5 | `TZ: Europe/Kiev` у `docker-compose.yml`: образ openHAB не знає такої назви | у логах контейнера `Invalid timezone 'Europe/Kiev'`, контейнер у стані Restarting | замінив на `Europe/Kyiv` |
| 6 | `keytool` створював truststore у форматі PKCS12 і падав, а truststore лише з нашим CA зробив би openHAB недовірливим до публічних сертифікатів | `keytool error: Illegal key size`, файл не створився | перейшов на формат JKS і додав системні сертифікати до truststore |
| 7 | у правилі PIN ШІ двічі запропонував `System::getenv(...)` (потім `java.lang.System::getenv`), але слово `System` зарезервоване в мові правил openHAB | `openhab.log`: `DSL model 'security.rules' has errors, therefore ignoring it: [58,15]`, після першої правки позиція змінилася на `[58,29]` | відмовився від читання змінної середовища: `setup.sh` кладе SHA-256 PIN у `pin.map`, правило бере його через `transform("MAP", ...)` |

## Що зроблено без ШІ

Створив репозиторій на GitHub, робив коміти та push, запускав Docker і симулятор, проводив усі тести й діагностику в терміналах (спроби підключення без пароля, публікація в чужий топік, перевірка портів, перевірка Last Will, прогін усіх сценаріїв), переглядав логи Mosquitto, контейнерів і openHAB, надсилав їх на розбір, створював файли й вставляв код у VS Code, робив усі скріншоти, вписав у README свої дані та виправляв його за результатами перевірок.

## Висновок

ШІ згенерував початкові версії конфігурацій, симулятора й правил, але частина з них не працювала з першого разу, і причини я знаходив за логами брокера, контейнерів та openHAB. Я розібрався, як працюють автентифікація й ACL в Mosquitto, TLS із власним CA, топіки та QoS в MQTT, Last Will, а також Things, Items і правила в openHAB. Найбільше часу забрали особливості Docker і Git Bash на Windows, а також синтаксис правил openHAB. Повторити роботу без ШІ мені було б складно без документації, але з документацією Mosquitto й openHAB та лекціями це можливо, хоча й довше.
